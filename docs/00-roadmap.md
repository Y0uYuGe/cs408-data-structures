## 一条贯穿全仓库的数据流

`笔记文件 → tokenize → 词频散列表 → term→有序docID倒排表 → 布尔解析栈 → 双指针合并 → 堆/排序 → JSON结果`。另外，正文长度进入AVL；词汇进入Trie；文档共享词构成图；全部文档进入Huffman备份。持久化保存原始文档及元信息，重启根据这些原始数据重建所有派生索引。

例如一篇笔记ID=1、正文`tree tree graph`，词频为`tree:2,graph:1`；另一篇ID=2、正文`tree`，两个倒排表为`tree:[1,2]`、`graph:[1]`。执行`tree AND NOT graph`先得到全集`[1,2]`减`[1]`为`[2]`，再与tree交集为`[2]`。这个例子贯穿线性表、栈、散列、查找和排序。

## 如何判定“学会”

能运行代码只是第一层。第二层是对未见过的小输入手算结果；第三层是解释不变量为什么在插删后仍成立；第四层是在C/C++中写出相同算法并分析复杂度；第五层是辨别题目条件变化，例如边权变负、比较概率不等、排序要求稳定、外存页数受限。

本仓库的`topics.json`是定位索引，不是“已讲透”的证明。`implemented`表示有相应实现及可检查行为；`theory`表示只有课程推演/测验，没有该结构的完整运行实现。考试大纲中的个别术语、题型和侧重需逐年核对。

## 导航练习及答案

练习：删除ID=1后，上例两个倒排表应是什么？为什么仅从文档表移除1不够？

答案：`tree:[2]`，graph词条消失；否则倒排表还指向不存在的文档，查询、排名、Trie联想、图构建均可能不一致。阅读`Engine._unindex`和`test_update_delete_remove_every_index_restart`验证这一点。
