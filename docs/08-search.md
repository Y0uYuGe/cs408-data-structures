# 08 查找、ASL、散列与多路树

级别4。代码`algorithms.py:binary_search`、`structures.py:HashMap/AVLTree`、`engine.py:locate_id/range`；命令`show ID --lookup hash|binary`在同一文档集合上切换实际查找策略。

## 顺序与折半

顺序查找无需有序，但成功等概率平均比较`(n+1)/2`次，失败n次；若使用哨兵会改变边界判断方式，不改变线性数量级。ASL是`Σpᵢcᵢ`，必须明确成功/失败、概率和比较次数的定义。

折半查找要求有序并支持高效按下标访问。本实现lower_bound用半开区间[lo,hi)，不变量是答案在该区间边界内：若a[mid]<target则lo=mid+1，否则hi=mid。`[1,3,3,9]`查3：lo0 hi4 mid2，a2=3使hi2；mid1=3使hi1；mid0=1使lo1；返回1，是第一个不小于3的位置。查4返回3，但该位置值9不是4，调用者要再验证相等。

系统binary查找每次先整理ID有序表，因此端到端命令还包含排序成本，不应只凭二分核心O(log n)声称整个show O(log n)。有序链表不能直接照搬数组二分得到O(log n)随机定位。

## 拉链散列

HashMap对UTF-8键逐字节计算确定性散列，以hash%桶数定位LinkedList，再比较完整key。碰撞是不同key落同桶，不能用桶号或hash值当相等条件。装填因子α=元素数/桶数，本实现超过.75倍增并把所有旧键重新分桶；只扩大数组不重算桶号会导致查找丢失。

若容量8、键a与b均落桶2，则链`[a,valueA]→[b,valueB]`。更新a只替换值不增加size；删除a不能清空整个桶，否则b丢失。None也是合法value，因此get默认None无法判断key是否存在，本实现用独特marker判断。

开放定址仅理论：线性探测沿`h,h+1,...`找槽，易产生聚集；平方探测与双散列改变探测序列。删除常需墓碑而不是“从未使用空槽”，否则查找沿探测链遇空提前结束。探测与装填要求因实现不同，不能照抄拉链法允许α>1的结论。

## AVL与B/B+树

AVL以比较键组织内存查找，插删保证O(log n)，范围查询约O(log n+k)。本系统二元键保证相同长度有稳定次序，边界`(min,0)`至`(max,next_id)`囊括全部目标长度ID。

B树结点可含多键、多孩子，在磁盘上一页放多分支以减高度；B+树内部结点主要作导航，所有记录在叶层，叶子通常按序链接，范围查找定位首叶后顺链扫描。阶m、最少孩子数、根特例等术语在不同教材有定义差异，应先按题目约定。以最大3孩子的小B树插入10,20,30，溢出后提升中键20，左右叶10/30；删除涉及借兄弟或合并，不能套AVL旋转。

本仓库实现AVL，B/B+树与开放定址只作理论推演，缺完整分裂/合并与磁盘页实现。精确边界见coverage。

## 练习与常见错误

练习1：比较次数1,2,2,3且等概率，ASL？答案2。练习2：n=12,m=16时α？答案.75。练习3：lower_bound返回len(a)意味？答案全部元素小于目标，无可用命中位置，不可直接索引。

练习4：两篇正文长度同为5，若AVL只用长度作key会怎样？答案后一篇覆盖前一篇，范围漏文档，必须用`(length,id)`或结点内桶。

常见错误：不写有序前提；混淆成功与失败ASL；散列碰撞当错误而不是正常情况；扩容不rehash；所有“树”都认为有O(log n)保证。
